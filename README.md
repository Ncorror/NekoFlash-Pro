# NekoFlash Pro — начало переписывания

Новый проект отделён от legacy NekoFlash 6.0.0-alpha11. Исходный код legacy не
включён в этот репозиторий: он служит источником проверенных протокольных правил
и сценариев для будущей проверки на устройствах. Контракт команд сверяется с
официальными Android SDK Platform-Tools 37.0.1.

## Что уже есть

- `:engine` — независимый от Android разбор терминальных команд в типизированные
  намерения. `format`, `-w`, `wipe-super`, `update`, `flashall` и сборка
  `vendor_boot:RAMDISK` не превращаются в обычные Fastboot wire-строки. Опции
  сохраняются. Неизвестная команда `adb` не заменяется на `shell`.
- `:core:transport` и `:core:fastboot` — порт транспорта, тестируемое распознавание
  интерфейсов ADB/Fastboot и первая проверяемая часть Fastboot wire-протокола:
  ответы `INFO`, `TEXT`, `OKAY`, `FAIL`, `DATA`;
  неподдержанная DATA-фаза закрывает сессию. Отдельный FakeTransport-тест
  проверяет два фиксированных запроса `getvar:version` и `getvar:product`.
- `:core:adb` — ограниченный ADB `CNXN`: отправляет один фиксированный пакет,
  разбирает первый ответ `CNXN`, `AUTH/TOKEN` или `STLS`, ограничивает размер
  ответа и сразу закрывает транспорт. Баннер и токен не сохраняются; JVM-тесты
  проверяют ошибки заголовка и ответ без авторизации.
- `:core:diagnostics` — независимая от Android запись диагностического ZIP и
  JVM-тесты его содержимого и безопасных имён файлов.
- `:app` — устанавливаемая **техническая сборка** с `applicationId`
  `com.ncorror.nekoflash.pro`. Экран написан заново на Compose; модель состояния,
  UI и Android USB-адаптер лежат в отдельных пакетах. Приложение перечисляет
  устройства, запрашивает доступ и распознаёт сигнатуру ADB/Fastboot и пару bulk
  IN/OUT. По явному нажатию выполняет только чтение двух переменных Fastboot через
  короткую USB-сессию; для ADB отдельная кнопка проверяет первый ответ без
  авторизации и сервисных команд. Соединение закрывается после ответа или ошибки.
- `.github/workflows/build.yml` — JVM-тесты, lint Android и debug APK
  на push, pull request и ручной запуск. APK и файлы с результатами тестов
  доступны как отдельные artifacts запуска.

**Прошивка, общий USB-транспорт команд, план исполнения, Preview, Sync v2 и большие
образы ещё не реализованы.** Успех CI подтверждает сборку технического APK и
тесты парсера, а не совместимость с устройствами или готовность P0.

Критерии P0 и точное состояние команд указаны в
[`docs/00_Command_Parity_P0.md`](docs/00_Command_Parity_P0.md). Обязательные
архитектурные решения собраны в [`docs/01_Decisions.md`](docs/01_Decisions.md).

## Сборка

На машине с JDK 17, Android SDK 36 и доступом к Gradle и Maven:

```sh
bash ./gradlew :engine:test :core:transport:test :core:fastboot:test :core:adb:test :core:diagnostics:test :app:lintDebug :app:assembleDebug
```

Debug APK окажется в `app/build/outputs/apk/debug/`. Подписанный релиз и
публикация APK пока не настроены. На GitHub тот же набор задач запускается
автоматически; APK скачивается с вкладки **Actions → Pro prototype build →
Artifacts** после успешного запуска. Секреты и release-ключ от legacy
сюда не переносятся.

Зафиксированы Gradle 9.5.0, Android Gradle Plugin 9.2.1, Kotlin/Compose
Compiler 2.4.20 и Compose BOM 2026.05.01. `compileSdk` 36, `targetSdk` 36.
Проверенные цвета legacy (`#080D13`, `#121A24`, `#E9782B`) используются в
новой тёмной теме; layout-код legacy сюда не переносится.

ID прежних технических APK был `ru.forum.nekoflash.pro`; новый APK с ID
`com.ncorror.nekoflash.pro` устанавливается отдельно. Старую техническую
сборку можно удалить. Каждый запуск CI пока подписывает debug APK временным
ключом, поэтому для замены будущих debug-сборок может требоваться удаление
предыдущей. Постоянная подпись релизов ещё не настроена.

В установленном APK подключите устройство через USB OTG, откройте приложение
и нажмите «Обновить USB-устройства». В списке видны VID:PID и текущее состояние
доступа и обнаруженный интерфейс ADB/Fastboot. Кнопка «Запросить доступ» вызывает
системный диалог Android; после подтверждения приложение показывает разрешение,
а обмен начинается только при нажатии кнопки проверки. В режиме Fastboot
после выдачи разрешения доступны отдельные кнопки для `getvar:version` и
`getvar:product`. Оба запроса только читают сведения. Устройство из ZIP
`23-05-30` ответило `FAILGetVar Variable Not found` на `getvar:version`, а ZIP
`23-21-44` дважды подтвердил `getvar:product` → `vayu`. В режиме ADB отдельная
кнопка отправляет только `CNXN` и фиксирует первый ответ. `AUTH` означает,
что требуется авторизация; приложение пока не отправляет ключ и не вызывает
диалог подтверждения на втором устройстве. Результаты находятся в `events.log`.
Успешная сборка CI не подтверждает работу ADB на конкретном телефоне.

Чтобы снять расширенную диагностику без компьютера и Termux, воспроизведите
проблему и нажмите **«Сохранить ZIP-отчёт»**. Android предложит выбрать папку.
Архив содержит `events.log` (до 256 КиБ событий), `environment.txt` (версия
приложения, Android, модель телефона, USB host и батарея),
`usb-descriptors.txt` (VID:PID, разрешение, конфигурации, интерфейсы,
конечные точки и распознанные сигнатуры ADB/Fastboot) и `README.txt`.
Серийный номер, баннер и токен ADB не записываются в архив и не показываются.
Полный системный logcat недоступен; текст ошибок Android может
содержать дополнительные детали — проверьте архив перед отправкой. Кнопка
**«Только события в TXT»** сохраняет прежний формат. Перечень шагов и результаты
есть в [`docs/02_Manual_Test_Plan.md`](docs/02_Manual_Test_Plan.md).

В каждом запуске Actions артефакт `NekoFlash-Pro-test-results-<номер>` содержит
`build/verification/test-summary.md`, исходные JUnit XML, HTML-отчёты тестов,
Android lint и план ручной проверки. Краткий итог также виден на странице запуска
в **Job summary**. При ошибке тестов доступные отчёты всё равно загружаются.

## Работа с репозиторием через Termux

Приватный репозиторий: `https://github.com/Ncorror/NekoFlash-Pro`.
На телефоне с авторизованным GitHub CLI можно получить исходники:

```sh
pkg install git gh
gh auth status
gh auth setup-git
gh repo clone Ncorror/NekoFlash-Pro
cd NekoFlash-Pro
```

Если `gh auth status` показывает отсутствие авторизации, выполните
`gh auth login` в Termux. Один раз задайте `git user.name` и `git user.email`,
если они ещё не настроены. После изменения файлов отправьте только выбранные
пути (папки тоже подходят):

```sh
git status --short
bash scripts/termux-push.sh "Обновил README" README.md
```

Скрипт проверяет аккаунт и адрес репозитория, получает новые коммиты с GitHub,
показывает файлы перед коммитом и ждёт подтверждения. Он не делает force push.
Если файлы уже добавлены через `git add`, можно вызвать скрипт только с
сообщением. После неудачного push повторный запуск отправит сохранённый
локальный коммит. Сборка автоматически запускается при push в `main` и при
pull request в `main`; APK и отчёты доступны во вкладке **Actions**.
