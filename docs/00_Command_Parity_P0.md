# Возможности и точный смысл команд

**Целевой контракт**, составленный по рефакторингу и вложенному legacy. Наличие команды в этом перечне не означает, что она работает в текущем APK. [Пооперационный статус](06_Roadmap.md).

| Область | Конечная возможность | В нынешнем прототипе |
| --- | --- | --- |
| USB | Обнаружение по дескрипторам, разрешение Android, владение сессией, повторное подключение | Обнаружение, разрешение и базовое владение есть |
| ADB | AUTH, многопоточные сервисы, `shell,v2`/fallback, интерактивный терминал, Sync push/pull, install, reboot, forward/reverse, raw service | AUTH и фиксированный диагностический запрос; общего сервиса/терминала пока нет |
| Fastboot | `getvar`, `download`, `flash`, `boot`, `erase`, `format`, слоты, fastbootd, OEM, DATA IN/OUT, raw | Чтение отдельных `getvar`; ограниченный raw-image `download` + `flash` без подтверждённой записи на устройстве |
| Recovery | Определение режима, журналы, request-driven Sideload, отдельный вердикт установки | Нет |
| Операции/файлы | Один владелец USB-операции, потоковые большие файлы SAF, стадии/прогресс/`Unknown`, восстановление отчёта | Нет полноценного длительного движка |
| Диагностика | Экспорт ZIP: структурированные события, USB/ADB/Fastboot, результат операции; без секретов | Небольшой ZIP и TXT уже есть |
| Mi Unlock | Отдельный пользовательский сценарий поверх общего Fastboot и vendor-клиента | Нет |
| Высокая скорость | Java USB как базовый путь; замеренный USBFS/URB backend и безопасный fallback | Native USBFS отсутствует |

## Команда на экране и команда на проводе

Команды настольных `adb`/`fastboot` могут быть **алгоритмами хоста**, а не одиночными строками USB. Для `flashall`, `update`, `-w`, `format`, установки пакетов, Sideload, размеров sparse и переключения слотов нужен собственный план с явным значением каждого параметра. Кнопка в UI и запись в терминале вызывают один и тот же движок. `raw` означает явную отправку wire-запроса; он не изображает исполнение команд настольного клиента.

Неизвестный `adb`-глагол не превращаем молча в `shell`. Параметр либо имеет эффект, либо команда получает `Unsupported` до отправки. Реальные `FAIL`/`OKAY` и ошибки транспорта показываются раздельно. Отсутствие реализации в текущем APK следует назвать отсутствием реализации, не выдавать его за отказ устройства.

Ранее P0 описывал почти весь конечный продукт как одно обязательство. Для работы теперь используется последовательность небольших этапов из [roadmap](06_Roadmap.md); полнота продукта проверяется по этой матрице, а не по прежнему названию P0.
