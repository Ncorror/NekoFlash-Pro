# Ручная проверка технической сборки на телефоне

Заполните дату, модель телефона, версию Android, номер GitHub Actions и
подключённое USB-устройство (VID:PID). Эта сборка выполняет выбранный
фиксированный запрос чтения `getvar:version` или `getvar:product` при явном
нажатии в Fastboot. В режиме ADB отдельно доступны проверка первого `CNXN`
без ключа и авторизация ключом с подтверждением на подключённом устройстве.
Запуск сервисов, терминал и прошивка пока не выполняются.

| № | Действие | Ожидаемый результат | Факт / статус |
| --- | --- | --- | --- |
| 1 | Запустить приложение без OTG, нажать «Обновить USB-устройства» | Приложение не закрывается; показан пустой список или сообщение об отсутствии USB host | |
| 2 | Подключить устройство по OTG и обновить список | Показаны количество устройств и VID:PID; нет команды прошивки | |
| 3 | Нажать «Запросить доступ» и отклонить диалог Android | Показано «Доступ не разрешён»; кнопку можно нажать снова | |
| 4 | Повторить запрос и разрешить доступ | Показано «Доступ разрешён» | |
| 5 | Отключить и снова подключить USB | Список и статус обновляются, приложение не закрывается | |
| 6 | Закрыть приложение, открыть снова и обновить список | Список соответствует текущему подключению | |
| 7 | Нажать «Сохранить ZIP-отчёт», выбрать папку | Архив создаётся и открывается; внутри `README.txt`, `environment.txt`, `usb-descriptors.txt`, `events.log` | |
| 8 | Проверить `usb-descriptors.txt` при подключённом USB | Видны VID:PID, разрешение, классы интерфейсов и параметры конечных точек; серийного номера и содержимого устройства нет | |
| 9 | Отключить USB и сохранить второй ZIP | В `events.log` есть событие отключения, а в `usb-descriptors.txt` устройство отсутствует | |
| 10 | Нажать «Только события в TXT» | Отдельный TXT сохраняется как раньше | |
| 11 | Подключить устройство с USB-интерфейсом ADB `FF/42/01` и обновить список | В карточке показан ADB и пара bulk IN/OUT, а также предупреждение «Соединение не проверено»; разрешение Android показано отдельно | |
| 12 | Сохранить ZIP с подключённым устройством | В `usb-descriptors.txt` есть строка `Recognized USB interfaces` и классификация ADB/Fastboot с состоянием bulk-пары; авторизация ADB явно отмечена как не проверенная | |
| 13 | Подключить устройство в режиме Fastboot и обновить список | Для интерфейса `FF/42/03` показан Fastboot; без нажатия кнопки команды не отправляются | |
| 14 | Разрешить USB-доступ к Fastboot-устройству и нажать «Прочитать версию протокола Fastboot» | Кнопка показывает ожидание, затем версию или ответ об отсутствии переменной; `FAIL` не маскируется под сбой USB | |
| 15 | Нажать «Прочитать код продукта Fastboot» и сохранить ZIP | В `events.log` видны запрос `getvar:product` и результат `VALUE` либо `REJECTED`; в `usb-descriptors.txt` Fastboot-интерфейс | |
| 16 | Отключить устройство во время ожидания ответа | Приложение не закрывается; старый ответ не показывается в карточке нового подключения; следующий запрос возможен | |
| 17 | Перевести устройство в обычный режим с включённой отладкой USB; выдать приложению USB-доступ и нажать «Проверить ответ ADB» | Показан первый ответ `AUTH` (нужен обмен ключами), `CNXN` (ответ на диагностическую сессию) или ошибка с причиной в журнале. Диалог подтверждения ключа не ожидается | |
| 18 | Сохранить ZIP после ADB-проверки | В `events.log` есть `ADB CNXN requested` и результат без токена, баннера или серийного номера; в `usb-descriptors.txt` интерфейс ADB и указатель на события | |
| 19 | Отключить USB во время ADB-проверки и подключить снова | Приложение не закрывается, результат старого подключения не показывается для нового устройства | |
| 20 | Нажать «Авторизовать ADB» после `AUTH`; разблокировать подключённое устройство | На подключённом устройстве появляется запрос отладки USB; подтвердить его; в приложении отображается ответ `CNXN`. Первая авторизация может занять время | |
| 21 | Снова нажать «Авторизовать ADB» после успешного шага 20 | При сохранённом ключе возможен `CNXN` после подписи токена без нового диалога | |
| 22 | При появлении ожидания нажать «Отменить ожидание», затем повторить проверку | Соединение закрывается; можно выполнить новый запрос; старый результат не появляется | |
| 23 | Оставить подтверждение на устройстве без ответа | Через две минуты ожидание завершается ошибкой, доступна новая попытка и ZIP с причиной | |
| 24 | Сохранить ZIP после авторизации | `events.log` содержит тип результата авторизации или сообщение об ошибке, но не содержит открытый ключ, подпись, токен или баннер | |

Отправляйте ZIP после воспроизведения проблемы. Если возникла ошибка, приложите
также краткое описание действия и скриншот. Журнал хранится внутри приложения,
ограничен последними 256 КиБ и удаляется вместе с приложением; экспортированный
ZIP или TXT остаётся там, куда вы его сохранили. Проверки выше нужно выполнить на
реальном устройстве: успешные JVM-тесты в CI не подтверждают работу USB OTG.

Автоматические тесты парсера команд, Fastboot wire, ADB первого ответа, авторизации
и ZIP находятся в
`engine/src/test`, `core/transport/src/test`, `core/fastboot/src/test`, `core/adb/src/test` и
`core/diagnostics/src/test`. Их JUnit XML, HTML-отчёты и итоговый
`build/verification/test-summary.md` публикуются в отдельном артефакте каждого
запуска Actions. Статус ручных проверок CI не выставляет.
