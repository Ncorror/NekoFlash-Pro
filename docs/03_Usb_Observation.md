# USB: установленное и требующее проверки

Исторические частные отчёты с телефонов не являются частью публичной рабочей документации. В этом файле остаются только общие выводы, необходимые для следующей разработки.

- Android USB-разрешение, ADB-авторизация и ответ конкретного ADB-сервиса — разные этапы. Распознанный интерфейс и предоставленное разрешение ещё не доказывают готовый `CNXN`.
- Для распознанного единственного ADB-устройства автоматический запрос USB-разрешения и попытка авторизации уже есть в APK. Если ключ не доверен, подтверждение выполняется на целевом устройстве. Отдельная read-only проба первого ответа без ключа может увидеть `AUTH` и после прежнего доверия; это не отменяет успешного независимого подключения.
- Fastboot `getvar` возвращает как `OKAY`, так и `FAIL`; оба ответа означают, что запрос дошёл до устройства. Диагностический запрос не доказывает работу DATA-фазы или корректность `flash`.
- Для существующего `download`/`flash` здесь нет подтверждённой успешной аппаратной записи. Аппаратные события из архивного рефакторинга и legacy не считаются проверкой данного APK. Текущий путь ограничивает размеры и не принимает sparse.
- Смена USB-режима, отсоединение и повторное подключение требуют нового поколения сессии; результаты прежнего подключения нельзя показывать как новые. Состояние загрузчика также заново определяется для новой Fastboot-сессии.

Следующий прогон описан в [плане ручной проверки](02_Manual_Test_Plan.md); реальный уровень готовности — в [roadmap](06_Roadmap.md). ZIP отчётов сохраняются отдельно от репозитория и просматриваются перед передачей.
