# Состояние и ближайшая работа

Дата сверки: 27 сентября 2026. **Статус относится только к репозиторию `Ncorror/NekoFlash-Pro`**, а не к вложенному архиву или legacy. `Код` означает наличие пути и тестов; `аппаратно подтверждено` означает проверку именно этого APK. CI подтверждает сборку и JVM-тесты, не физический исход прошивки.

| Возможность | Код здесь | Код в предоставленном рефакторинге | Что осталось подтвердить здесь |
| --- | --- | --- | --- |
| USB discovery/permission/auto ADB AUTH | Частично работает | API + Android USB/session модель | Полная обработка смены поколения и выбранного target |
| ADB generic streams, Shell/Sync/forwarding | Нет общего API | Реализованы части protocol + UI | Перенос, fault tests, затем аппаратные сценарии |
| Fastboot чтение `getvar` | Ограниченные запросы | Единая lane/команды/переменные | Свести UI/raw в общий движок |
| Fastboot DATA OUT и запись | Ограниченный исполнитель raw image | Download/планы/мутации | Проверить wire DATA, совместимость файла, реальный итог; успешная запись здесь **не подтверждена** |
| Fastboot DATA IN/fastbootd/слоты/sparse | Нет | Есть части fetch/определения режима/слотов; полнота требует сверки | Реализовать host-планы и отдельные тесты |
| Recovery и Sideload | Нет | Есть protocol-классы и UI-сценарий | Завершить проверку установки отдельно от передачи |
| Операции и большие файлы SAF | Только короткие действия и выбор образа | Operation/artifact модели, streaming | Встроить lifecycle, отмену и `Unknown` без ложного resume |
| Диагностика | ZIP/TXT, есть события и USB-описание | Структурированный ZIP/события | Объединить схему, privacy audit, прикреплять исход операции |
| Бренд и многоязычный UI | Тёмная оранжевая тема, первичный экран | Welcome, более полная навигация и ресурсы | Собрать целостный интерфейс из legacy-идеи и модульного UI |
| Mi Unlock | Нет | В рефакторинге не отдельный готовый модуль; есть reference legacy | Отдельный vendor workflow после устойчивого core |
| Fastboot высокая скорость | Нет нативного backend | Вложенные legacy/A2 имеют USBFS; рефакторинг планирует новый `usb:native` | Измерить базовый путь и спроектировать безопасный native backend |

## Порядок работы до очередных тестов на телефоне

1. Зафиксировать этот статус и границу версии. Снять конфликт идентичности APK и debug-подписи: решение должно сохранять предсказуемую ADB-авторизацию при установке следующей сборки.
2. Выбрать единые модели target/session/USB из архива и сопоставить с `:core:transport`. Сначала короткий сквозной путь подключения, без большой замены всего проекта.
3. Перенести общий ADB connection/dispatcher и Fastboot lane с тестами ошибок/обрыва. У UI и raw терминала должен быть один протокольный путь.
4. Добавить operation/artifact слой для настоящих файлов, затем привести Fastboot `download`, sparse/размеры и диагностику в соответствие с техническими инвариантами.
5. Подготовить документацию действий на устройстве и APK. Аппаратные проверки вести на одном согласованном тестовом устройстве с разблокированным загрузчиком, сначала read-only и затем только с проверенным образом и назначением.
6. После достоверного базового DATA OUT замерить скорость. При необходимости перенести USBFS/URB из legacy как новый backend с отдельным стресс-тестом отмены/отсоединения; не обещать ускорение без измерения.
7. Далее Recovery/Sideload, полная поверхность ADB/Fastboot, долгие операции, Mi Unlock и финальный UI.

Пункты меняют статус только после соответствующего кода, CI и, где требуется, отдельной аппаратной проверки. Исторические прогонки из архивных документов полезны как шаблон сценариев, но не как отметка «готово» для этой ветки.
