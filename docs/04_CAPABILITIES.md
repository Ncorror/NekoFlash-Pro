# Возможности

Полный **целевой** набор функций NekoFlash. Статусов здесь нет и быть не должно: что сделано, а что нет — только в [05_ROADMAP](05_ROADMAP.md). Колонка «Опыт» говорит, где смотреть проверенное поведение ([06_MIGRATION](06_MIGRATION.md#6-где-смотреть-поведение-перед-реализацией)), а не что уже работает.

Живое испытание разблокировки остаётся отдельным пунктом [плана](05_ROADMAP.md).

### Когда возможность считается восстановленной

1. есть один production API;
2. модель транспорта и ошибок не прячет ответ устройства;
3. определены владение и отмена;
4. есть тесты, включая отказы;
5. чувствительная к железу часть проверена на реальном устройстве с APK этого репозитория;
6. интерфейс и сырой доступ используют одно ядро;
7. второго старого пути нет.

## 2. Три способа сказать одно и то же

Пользователь может обратиться к одной возможности тремя способами, и **все три идут в один и тот же движок**:

| Способ | Что это | Проверка |
| --- | --- | --- |
| Кнопки и формы | типизированные действия с предпроверкой и подтверждением | предупреждения класса C, подтверждение класса D |
| Сырая консоль | wire-запрос устройству как набран: Fastboot-команда или имя ADB-сервиса | без подтверждений и без списков; только корректность кадра |
| Команды настольных `adb`/`fastboot` | привычная строка `fastboot flash boot_a boot.img` → план шагов → Preview → выполнение | как у кнопок: это тот же сценарий, записанный текстом |

## 3. Команды настольных `adb` и `fastboot`

Эталон — справка официальных Android SDK Platform-Tools 37.0.1. Команды настольных клиентов бывают тремя разными вещами: операцией хоста, wire-сервисом и составным планом. **Парсер не выдаёт одно за другое.**

### Правила

1. Пользователь выбирает раздел, слот, файл и команду. Сведения об устройстве помогают и предупреждают, но не служат списком разрешённых целей.
2. Параметр либо действует, либо команда завершается явной ошибкой **до отправки**. Молча игнорировать `-S`, `--force`, `--set-active` и другие опции нельзя.
3. Известная команда создаёт типизированное намерение; известная команда хоста без реализации получает «не реализовано». Неизвестный глагол Fastboot уходит как vendor wire-команда. Неизвестный глагол `adb` **не** превращается в `shell`.
4. `raw` — явная отправка wire-запроса без нормализации; грамматика настольного клиента к нему не применяется.
5. Ошибки устройства, отсутствующие возможности и нарушения формата показываются отдельно от локальных ошибок разбора. Ожидание ответа пользователя на устройстве не обрывается общим дедлайном приложения.
6. Preview строится из того же плана, который исполняется. Исполнитель не возвращает успех для неподдержанного шага.
7. Путь к файлу в команде не открывается напрямую: файл выбирается через Android и привязывается к проверенному плану.

### Точный смысл

| Команда | Что обязан сделать исполнитель |
| --- | --- |
| `fastboot format[:TYPE[:SIZE]] PARTITION` | узнать параметры раздела, создать подходящую ФС и записать её; не отправлять `format:PARTITION` как есть |
| `fastboot -w [COMMAND]` | полный сценарий wipe хоста (`userdata`, `cache`, `metadata` и форматирование, где применимо); сочетание с `COMMAND` сохраняется |
| `fastboot wipe-super [SUPER_EMPTY]` | прочитать метаданные, собрать и записать пустой super; не отправлять `wipe-super` как wire-команду |
| `--set-active`, `--slot`, `-S`, `--force`, `--skip-*`, флаги vbmeta | учесть в плане совместимых команд; каждая несовместимость диагностируется до исполнения |
| `fastboot flash`, `flash vendor_boot:RAMDISK`, `boot`, `flash:raw`, `update`, `flashall` | подготовить образы и план на хосте с учётом слотов, fastbootd, sparse/resparse и `max-download-size`; `vendor_boot:RAMDISK` требует fetch и перепаковки |
| `fastboot getvar`, `reboot*`, `oem`, `flashing`, `gsi`, `snapshot-update`, `*-logical-partition` | соответствующие wire-команды с сохранением аргументов |
| `adb shell`, `exec`, `logcat` | правильный сервис и режим (`shell,v2`, PTY, `-x`), коды выхода, отмена, ограниченная память для долгого вывода |
| `adb push`, `pull`, `sync` | рекурсивность и опции CLI; Sync v2 при поддержке устройством с откатом на v1 |
| `adb install`, `install-multiple`, `sideload` | точные сценарии хоста; `install-multiple` с одним APK допустим |
| `adb reboot`, `root`, `unroot`, `remount`, `usb`, `tcpip`, `uninstall` | нужные сервисы и корректное состояние сессии после ожидаемого отключения; `tcpip` предупреждает о потере USB |
| `adb raw`, `fastboot raw` | передать wire-запрос без подмены и без списка разрешённых имён |

Команды Platform-Tools вне этого списка (`adb pair/connect`, `install-multi-package`, `bugreport` и другие) получают свой тип намерения, когда появляется реализация; до тех пор парсер честно отвечает «не реализовано», а сырой сервис остаётся доступен.
