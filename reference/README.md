# Справочные архивы

Здесь лежат неизменяемые снимки, из которых мы переносим код и берём проверенное поведение. Это **не** исходники приложения: сборка их не использует, код из них попадает в модули только через перенос по [плану](../docs/06_MIGRATION.md).

| Файл | Что внутри | Происхождение |
| --- | --- | --- |
| `archives/NekoFlash-main-2026-09-14.zip` | Рефакторинг NekoFlash: 9 модулей (`app`, `core:*`, `usb:*`, `protocol:*`), 850 тестов, документы `docs/`, ADR. Внутри — `reference/archives/` со снимками legacy, A2 и первичной спецификации | Репозиторий `Ncorror/NekoFlash`, коммит `0be9ca786a756c5243be812096fe52b558af6113` (записан в комментарии ZIP) |

Вложенные снимки внутри архива:

- `NekoFlash-main-legacy.zip` — старое приложение (`ru.forum.adbfastboottool`): функции, бренд, Mi Unlock, `native_usbfs.cpp`;
- `NekoFlash-A2-frozen.zip` — экспериментальная ветка A2: USB, ADB framing, Sideload, отмена/drain;
- `NekoFlash-canonical-20260827.zip` — первичная спецификация проекта.

Их суммы сверены с `reference/SHA256SUMS` внутри архива.

## Правила

- Архив после коммита не заменяется и не редактируется. Новый снимок — новый файл с датой в имени и новая строка в `SHA256SUMS`.
- Проверка целостности (её же выполняет CI):

  ```sh
  cd reference/archives && sha256sum -c ../SHA256SUMS
  ```

- Распаковывать для работы — во временную папку вне дерева репозитория:

  ```sh
  mkdir -p /tmp/nf && unzip -q reference/archives/NekoFlash-main-2026-09-14.zip -d /tmp/nf
  ```

- Документы внутри архива — источник опыта и обоснований, а не действующие правила. Действующие правила — только в [`docs/`](../docs/README.md).
